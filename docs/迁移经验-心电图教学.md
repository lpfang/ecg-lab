# 从「断层解剖 · 3D 对照」到心电图教学：可迁移的经验

本文总结 anatomy-lab（https://lpfang.github.io/anatomy-lab/）的做法和踩过的坑，供新开一个心电图（ECG）教学项目时参考。
新项目可以把本文复制到项目根目录，作为给开发者（或 Claude）的背景说明。

---

## 一、核心教学思路（最值得迁移）

anatomy-lab 的核心是**「原始数据 ↔ 立体结构」双向对照**：在 CT/MRI 切片上点一个结构，3D 模型同步高亮，反之亦然。
心电图有完全对应的结构：

| anatomy-lab | 心电图项目中的对应 |
|---|---|
| CT / MRI 切片（原始数据） | 12 导联心电波形（原始数据） |
| 3D 器官模型 | 3D 心脏 + 传导系统动画 / 心电向量环 / 胸前导联电极位置 |
| 点切片 ↔ 3D 高亮 | 点某个波（如 V1 的 QRS）↔ 3D 显示此刻的除极方向和该导联的"视角" |
| 标签彩色叠加，可关掉看原片 | P / QRS / T 分段着色，可关掉看原始波形 |
| 窗宽窗位 | 走纸速度（25 / 50 mm/s）、增益（5 / 10 / 20 mm/mV）、滤波 |
| CT 值实测（鼠标悬停显示 HU） | 电子卡尺：测 PR、QRS、QT/QTc、心率、振幅 |
| 多个增强期相对比 | 同一患者治疗前后、或不同心律的病例对比 |
| 方位约定（屏幕左 = 患者右） | 导联极性、电轴六轴系统、胸导联的水平面"视角" |

**设计原则（已验证有效）：**
- **先看原始数据，再看标注**：导览的第一步关掉彩色标签，让学生先看灰度片子 / 纯波形。
- **实测值优先于教科书数值**：导览里实时显示本病例的测量值，并指出与教科书的差异（例如本项目里"右肾反而比左肾高"）。心电图同理：本例 QTc 是多少、电轴多少度。
- **中英对照**：结构名、术语都给出中英文（心电图术语更需要，如 "ST elevation / ST 段抬高"）。
- **四种学习方式并存**：自由浏览 → 导览（教师预设路线）→ 心电图手册（原理）→ 测验（自测）。手册每章都能一键跳到对应导览，导览每步都能回到手册对应章节。

## 二、功能模块与可复用的设计

### 1. 导览（Guided tours）
- **用数据描述步骤，不写死在代码里**：每步是一个对象（标题、讲解、要选中的结构、窗位、视角……），播放器统一解释执行。新增路线只需加数据。
- **按"结构是否存在"自动筛选**：步骤声明 `requires`，病例缺少相应结构时自动跳过；整条路线不足 2 步就不显示。
- **引用了具体病例数值的路线，必须限定病例**（`cases: [...]`）。本项目曾因为"本例门静脉期"这类讲解出现在别的病例里而出错。
- **跨病例串联**：最后一步可以带"继续：下一个病例 →"按钮（本项目用于肾的三个增强期相）。心电图可用于"正常 → 一度 AVB → 二度 I 型 → 三度 AVB"这类渐进对比。
- **实测表（probe）**：步骤可要求在面板中列出若干结构的实测中位数。心电图对应：列出各导联的 ST 偏移、各间期。

### 2. 测验
- 三种题型对应三种能力：**看名称找位置**、**看 3D 找原始数据**、**看原始数据认结构**。
  心电图对应：「找出 V1 的 P 波」「看向量环判断是哪个导联」「这段节律是什么」。
- 干扰项选**空间上最邻近 / 形态最相似**的结构，题目才有区分度。
- 作答时**遮蔽名称、锁定会泄露答案或破坏题面的控件**（本项目曾漏掉"答题中可重新开剖切"）。
- 判分容差按**物理单位**（mm、ms）计算，不按像素或采样点数，否则不同分辨率 / 采样率的病例标准不一致。

### 3. 心电图手册
- 章节分组：总览 → 各模态原理 → 系统专题；每章附"在图像上演示"按钮。
- **交互式小演示**最受欢迎（本项目的窗宽窗位滑块演示）。心电图可做：拖动电轴看六个肢导联波形如何变化；调心率看 QT 如何变化。
- 表格要**一行一个概念**，不要用"A / B"合并（用户读不懂"松质骨 / 皮质骨 200~400 / > 1000"）。

## 三、数据：来源、许可与流水线

### 1. 开放数据（立项时务必逐一核实许可）

以下为常用公开心电数据库，**许可与版本请以官方页面为准**：

| 数据库 | 内容 | 特点 |
|---|---|---|
| PTB-XL（PhysioNet） | 约 2.2 万条 10 秒 12 导联，500 Hz | 有 SCP-ECG 诊断标签，规模大，适合挑选典型病例 |
| PTB-XL+ | PTB-XL 的派生特征 | 含自动提取的波形特征点和测量值 |
| LUDB（PhysioNet） | 200 条 10 秒 12 导联，500 Hz | **心内科医生手工标注 P / QRS / T 起止点**，最适合做"波段着色" |
| MIT-BIH Arrhythmia（PhysioNet） | 48 段约 30 分钟双导联动态心电，360 Hz | 逐搏心律标注，适合心律失常长条带 |

3D 心脏模型需要另找许可合适的来源（开放解剖模型库，或开源分割模型生成），同样要核实许可、保留署名。

### 2. 流水线经验
- **按需下载单个病例**：本项目用 HTTP Range 只取压缩包中需要的文件，不下载整个数据集。PhysioNet 数据可直接按记录下载。
- **预处理成紧凑的静态资源**：Python 把原始数据转成"二进制数组 + gzip + meta.json"，前端直接读取。心电图数据量小得多（10 秒 × 12 导联 × 500 Hz ≈ 6 万个采样点），可以一个病例一个 JSON 或 Int16 数组。
- **统一采样率和单位**：不同数据库采样率不同（500 / 360 Hz），预处理时统一（或在 meta 里写明），所有测量都换算成 ms 和 mV。
- **一个 `index.json` 列出所有病例**，每个病例一个 `meta.json`，可选 `info.json` 覆盖描述和来源。
- **原始数据不进 git，处理后的数据进 git**（便于静态部署）；但要注意仓库体积，本项目仓库因 CT 数据已有数百 MB。
- **重建时检查"数据真的变了吗"**：gzip 每次输出字节不同，内容相同时应还原，避免仓库无意义膨胀。

### 3. 自动标注的教训
- 自动生成的标注**必须标明"未经人工校对"**，并请专业老师抽查。
- 本项目曾因标注重叠被静默覆盖，导致下颌骨 98% 丢失，长期无人发现。**流水线要报告冲突，不能静默处理**。
  心电图对应：自动检测的波形起止点与人工标注冲突、导联缺失、信号饱和，都要显式报告。
- 标注太小或被截断的结构（本项目的甲状软骨被扫描范围截断），在界面上**明确提示**，不要假装完整。
  心电图对应：导联脱落、基线漂移严重的片段要标出来。

## 四、技术架构（可直接沿用）

- **纯静态网站**：Vite + 原生 JavaScript + three.js（3D）+ Canvas 2D（波形 / 切片），无后端。
- **GitHub Pages + GitHub Actions 自动部署**：推送到 main 即发布。
- **浏览器缓存**：构建工具给 JS / CSS 加指纹文件名；数据文件 URL 加 `?v=<构建号>`。
- **全局 state 对象 + 各视图订阅重绘**：用 requestAnimationFrame 合并重绘。
- **重的部分（3D）与核心功能（2D）解耦**：3D 加载慢或失败时，二维阅片、导览、测验照常可用，3D 面板内显示失败原因和"重试"。
- **URL 参数**：`?case=<id>&tour=<id>` 直接打开某病例某导览；无效 ID 回退到默认病例并提示。

### 心电图特有的技术要点
- **按真实物理尺寸绘制**：标准心电图纸 1 mm 小格 = 40 ms × 0.1 mV。要按屏幕 DPI 和缩放换算，网格、卡尺都以 mm / ms / mV 为单位。
- **12 导联的标准排版**（3×4 + 节律条），以及导联顺序、标定脉冲。
- **滤波要可控并标明**：0.05–150 Hz 诊断模式 vs 0.5–40 Hz 监护模式，滤波会改变 ST 段，这本身就是教学点。
- **时间轴联动**：波形上的时间光标 ↔ 3D 心脏除极动画的当前时刻 ↔ 向量环上的当前点。

## 五、踩坑清单（最值得避免）

**异步与状态**
1. **异步请求必须可作废**：用户切换步骤、退出导览、返回列表时，旧请求返回后不能再改界面。用"令牌"标记最新请求；"下载"和"提交"分两步，提交前检查令牌。
2. **失败要有反馈和重试**：下载失败时停留在当前步骤并提供重试，不要让索引前进、界面停在半新半旧状态。
3. **进入某种模式时保存用户设置，退出时恢复**：导览、测验都会改隐藏、剖切、透明度等，退出时必须还原。
4. **"最新意图优先"**：3D 未就绪时记下的相机方向，若之后用户又做了操作，应以最新操作为准。
5. **启动失败不能锁死整个页面**：全屏加载层只等核心数据，可选模块异步加载。

**几何与测量**
6. **不要假设坐标轴正交**：本项目一例 CT 带 3.7° 倾斜，剖切面偏差 26 mm。心电图对应：不同设备的增益、采样率、导联顺序都可能不同，一律从元数据读取。
7. **测量和判定都用物理单位**（mm、ms、mV），不用像素或采样点。

**界面**
8. **默认显示的数值要在常见屏幕上可见**：本项目曾为了顶栏不拥挤，把窗宽窗位读数在小于 1750 px 的屏幕上隐藏，用户以为功能坏了。
9. **Mac 触控板**：右键拖动难以操作，提供 Ctrl / ⌘ + 左键的替代方式。
10. **从一开始就考虑手机端**：本项目到最后也没做好移动端（布局溢出、无触屏翻页手势）。心电图在手机上看的需求更大，建议一开始就做响应式和触屏手势。
11. **被隐藏 / 被禁用的东西要有一致的视觉表现**（本项目曾出现"隐藏的结构仍有描边"）。

**部署与工具**
12. **不要高频轮询 GitHub API**：本项目同时开了多个高频查询部署状态的后台任务，耗尽了每小时 5000 次的额度。轮询间隔至少 30 秒，同一时刻只开一个。
13. **部署卡住时先看日志**：本项目一次部署卡了两个多小时，真实原因是 GitHub 上传服务出错、失败的运行未能结束并占住并发组，而不是最初猜测的运行器问题。
14. **教学文字里的"本例……"必须与病例绑定**。

## 六、工作方法（本项目验证有效的节奏）

1. **先构思 → 搜索同类系统 → 做 MVP**，MVP 只覆盖一个病例、核心联动。
2. 再按"测验 → 多病例 → 导览 → 心电图手册 → 专题"逐步扩展，每步都在浏览器里实际点一遍再提交。
3. **独立复审很有价值**：本项目经历了 5 轮外部复审，共发现约 16 个真实问题（异步竞态、数据覆盖、几何偏差等），大多是单人开发时难以发现的。建议每完成一个阶段就做一次代码复审 + 浏览器端到端测试。
4. 每个改动都用**可复现的验证**：例如"把模型文件临时改名模拟下载失败""人为延迟请求 2 秒再退出导览"。
5. **医学内容需要专业审定**：本项目所有讲解文字和自动分割都未经专业老师逐条审核，页面上已注明。心电图诊断标准（如 STEMI 判定、QTc 公式选择）更需要心内科老师把关。

## 七、新项目启动清单

- [ ] 确定目标学员（医学生 / 规培 / 护理）和首批教学主题（如：正常心电图、电轴、房室传导阻滞、束支阻滞、心肌梗死定位、常见心律失常）
